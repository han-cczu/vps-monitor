# 步骤 16 · 限额与到期执行

> 阶段 4 · 依赖：15 · 粗估 3 天 · 对应设计方案 §4.6 规则、§6.6 enforce、§6.8

## 1. 目标

订阅用户的额度与到期自动生效：超额或到期自动从所有节点移除，重置日清零并恢复；变更合并下发、失败重试；前端显示状态与账期信息。

## 2. 范围

**做**：`proxy/enforce` 评估器与定时任务、账期滚动、与 Reconciler 的联动、重试与事件、前端状态与账期展示、汇总条计数、单测。

**不做**：告警通知渠道（19，此处只产生事件）。

## 3. 前置条件

步骤 15（用量在累计、订阅可用）。

## 4. 实现方案

### 4.1 评估器 `proxy/enforce/evaluate.go`

```go
type Decision struct { AutoDisabled string /* none|quota|expired */; Changed bool; Reason string }
func Evaluate(s store.Subscriber, now time.Time, loc *time.Location) Decision
```

规则（纯函数，表驱动单测）：

1. `enabled == false` → 不改 `auto_disabled`（手动停用优先，评估器不碰）
2. `expire_at != null && now >= expire_at 当日 24:00（面板时区）` → `expired`
3. 否则 `traffic_limit > 0 && traffic_used >= traffic_limit` → `quota`
4. 否则 → `none`
5. `Changed = 新值 != 旧值`

优先级：expired 高于 quota（到期了额度也没意义）。

### 4.2 定时任务 `proxy/enforce/job.go`

每 60 s（紧接步骤 13 的统计落库之后，同一轮）：

1. 读全部订阅用户 → `Evaluate` → 有变更的：更新 `auto_disabled`，审计 `actor="system"`、`action="subscriber.auto_disable"/"subscriber.auto_restore"`，发事件 `SubscriberQuotaExceeded / SubscriberExpired / SubscriberRestored`（19 订阅）
2. 对每个变更用户，找其分配涉及的节点集合 → `Reconciler.NodeChanged(serverID, "enforce")`（步骤 13 的 5 s 合并会把同一轮多个用户的变化合成一次下发）
3. 用量提醒事件：`traffic_used/limit` 首次跨过 80% 发 `SubscriberQuotaWarning`（在 `subscribers` 加 `warned_80 INTEGER` 列，账期滚动时清零；迁移 `0007_enforce.sql`）

### 4.3 账期滚动 `proxy/enforce/rollover.go`

每日 00:00（面板时区）：

- 对 `reset_day > 0` 的用户：今天的日号等于 `reset_day`，或 `reset_day > 当月天数` 且今天是当月最后一天 → 新账期：`period_start = 今天零点`、`traffic_used = 0`、`warned_80 = 0`；`auto_disabled == quota` → 置 `none`（自动恢复）→ `NodeChanged`
- `reset_day == 0` 的用户永不重置（一次性额度）
- 幂等：记录 `settings.enforce.last_rollover_date`，启动时若漏掉某天（面板停机）补跑一次

### 4.4 与 API 的联动

- `PUT /api/subscribers/{id}`：修改 `traffic_limit`、`expire_at`、`enabled` 后**立即**跑一次该用户的 `Evaluate`（不等下一分钟），让"给他加 50 GB"马上恢复
- `POST /reset-usage`：`traffic_used=0`、`warned_80=0`，评估，`NodeChanged`
- 列表与详情接口返回 `period_start`、`next_reset_date`（计算值）、`auto_disabled`、`status`（`active | disabled | quota | expired` 合成值）

### 4.5 Reconciler 重试补充（在 13 基础上）

失败重试 10 s / 30 s / 60 s 后仍失败 → 事件 `CoreApplyFailed` 已有；此处补充：节点重新上线（`hello`）时清除失败计数重新尝试。

### 4.6 前端

- 订阅用户列表：状态 `Label` 四态（正常绿 / 手动停用灰 / 超额停用橙 / 到期停用红）；用量列下方小字 `本期 9/1 起 · 10/1 重置`（`reset_day=0` 显示"不重置"）；到期列小于 7 天红字
- 详情页：账期卡（起止、已用/上限、剩余天数）；"清零用量"按钮确认文案说明会立即恢复
- 表单额度 Tab：重置日说明文字："每月该日零点清零；选 0 表示总额度用完即止"
- 监控总览汇总条：`超额/到期停用 N 人`（从 `/api/subscribers` 计数，SWR 60 s）

### 4.7 统计方向的可配项

`settings.enforce.count_mode`：`sum`（默认，上传+下载）或 `download`；影响步骤 13 中 `traffic_used` 的汇总 SQL。设置页加一个下拉，改动后下一分钟生效（不回溯）。

## 5. 接口与数据

| 类型 | 内容 |
|---|---|
| 表 | `subscribers` 新增 `warned_80` |
| settings | `enforce.last_rollover_date`、`enforce.count_mode` |
| REST | 订阅用户接口新增 `status`、`period_start`、`next_reset_date` |
| 事件 | `SubscriberQuotaWarning`、`SubscriberQuotaExceeded`、`SubscriberExpired`、`SubscriberRestored` |

## 6. 验收标准

- [x] `Evaluate` 表驱动单测：手动停用不变、到期优先于超额、恰好等于上限算超额、跨时区到期日边界
- [x] 给测试用户设上限 100 MB，Clash 下载 150 MB → 2 分钟内状态变"超额停用"、节点配置里用户消失、Clash 连接失败、订阅刷新得到空列表与注释（实测使用 100/150 MiB，Mihomo 真实传输）
- [x] 把上限改为 1 GB → 10 s 内恢复（实测 1 GiB，无需等下一分钟）
- [x] 把 `period_start` 手工改到上月、`reset_day` 设为今天 → 触发滚动 → 用量清零、状态恢复（事务测试；同时设置内部日期锚）
- [x] 到期日设为昨天 → 下一分钟变"到期停用"；改到明天 → 恢复（真实客户端）
- [x] 同一分钟 3 个用户同时超额且都在同一节点 → 只下发一次（服务通知去重与事务测试）
- [x] 面板停机跨过 00:00 再启动 → 补跑滚动（重启/跨日确定性测试）
- [x] 80% 事件只发一次；账期滚动后可再次发

## 7. 风险与注意

- 评估与统计落库在同一轮里顺序执行，避免用过期的 `traffic_used` 判断。
- 自动停用只改 `auto_disabled`，绝不动 `enabled`，否则会覆盖管理员意图。
- 到期判断以面板时区当日 24:00 为界，与用户理解的"到某天为止"一致。
