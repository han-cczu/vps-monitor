## 4. 实现方案

### 4.1 WS 客户端 `web/src/ws/client.ts`

```ts
export type WsStatus = 'connecting' | 'open' | 'closed';
export function startRealtime(getToken: () => string | null): () => void
```

- URL：`(location.protocol === 'https:' ? 'wss' : 'ws') + '//' + location.host + '/api/ws'`
- `onopen` → 发 `{type:'auth', token}`；收到 `snapshot` → `store.applySnapshot()`
- 断开重连：1s 起指数退避到 30s；`visibilitychange` 回到前台时立即重连
- 在 `AuthProvider` 之后的顶层组件里启动（登录态才连），登出时关闭

### 4.2 实时 store `web/src/store/realtime.ts`

```ts
type State = {
  status: WsStatus; ts: number;
  servers: Record<number, ServerSnapshot>; order: number[];
  applySnapshot(s: Snapshot): void; setStatus(s: WsStatus): void;
};
export const useRealtime = create<State>(...)
export const useServer = (id: number) => useRealtime(s => s.servers[id]);   // 卡片只订阅自己
export const useServerIds = () => useRealtime(s => s.order);
```

`applySnapshot` 用浅比较避免无变化的节点触发重渲染（十几台每秒一次本来也不重，但养成习惯）。类型 `ServerSnapshot` 放 `web/src/types/realtime.ts`，与服务端 snapshot 字段一一对应。

## 9. 偏离记录

1. **通用格式化与域常量提到了共享位置。** 文档 §4.5 要求新建 `web/src/utils/format.ts` 并把 `formatPrice`、`daysUntil` 放进去，但这两个函数步骤 03 已经写在 `sections/servers/utils.ts` 里了，而 `formatPrice` 依赖该 section 的货币符号与账期文案常量。为了不出现两份实现：
   - `sections/servers/constants.ts` → `src/constants/server.ts`（两个页面都要用同一套货币符号与账期文案）
   - `formatPrice` / `daysUntil` → `src/utils/format.ts`，与新写的 `formatBytes` / `formatRate` / `formatPercent` / `formatDuration` 放在一起
   - `sections/servers/utils.ts` 只保留表单专用的 GB/TB 双向换算与地区文案
   `servers-list-view.tsx` 与 `server-form-dialog.tsx` 的 import 跟着改。行为上有一处细微变化：原 `formatPrice` 对非整数价格用 `round2(price).toFixed(2)`（`168.5` → `168.50`），新实现用去尾零的 `trimNumber`（`168.5` → `168.5`）。

2. **`formatBytes` 默认 1000 进制。** 文档 §4.5 说"`base` 先固定 1000"，这里做成了可选参数 `{ base: 1000 | 1024 }` 默认 1000，步骤 20 接设置项时不用改调用点。注意与 `sections/servers/utils.ts` 里表单用的 1024 进制是两套：那边是"商家标称的 1 TB 套餐"，按 1024 填会对不上账。

3. **卡片组件没有按文档 §4.3 拆成 10 个文件。** `totals-row` / `traffic-row` / `ping-rows` / `card-footer` 四块都只有几十行，合并成一个 `card-rows.tsx`；`stat-block` / `segment-bar` / `net-row` / `sparkline` / `card-header` 按文档单独成文件。拆得过细的代价是每个文件都要重复一遍 import 块，读起来反而更累。

4. **`ping-rows` 没有实现。** `ping` 恒为空数组（步骤 09 才有数据），写一个"永远返回 null"的组件是死代码。类型里保留了字段，卡片里不渲染这一块。

5. **卡片右上角没有「详情 / 更多」按钮。** 文档 §4.3 要求放两个图标按钮，但详情页要到步骤 08 才有路由（`paths.dashboard.servers.details(id)` 在 `paths.ts` 里预留了，路由表里没注册），"更多"菜单现在也没有任何可做的操作。放两个点了没反应的按钮不如不放。右上角改成放离线标签。

6. **三个文档没写、实现时定下来的显示规则**：
   - 离线节点保留最后一帧的数值而不是清零（服务端也是这么存的），整卡 `opacity: 0.55`
   - 从没连过的节点显示「未连接」而不是「离线 N 分钟」——它没有 `last_seen`，算不出时长
   - 负载没有天然的百分比，分段条按「每核 1.0 算满」折算（`load[0] / cores`），多核机器才不会一直顶格

7. **汇总条的「即将到期」是真算的，「本月流量」才是占位。** 文档 §4.3 把两个都写成占位，但 `expire_at` 在快照里就有，30 天内到期的数量直接能算。本月流量要等步骤 18 的结算，显示 `—` 并在 tooltip 里说明。

8. **上下行速率只累加在线节点。** 离线节点的 `net.up` 是最后一帧的旧值，累加进"全站总上行"会让数字虚高一截。

9. **验收第 6 条用 MutationObserver 代替 React DevTools Profiler。** headless Edge 里装不了 DevTools 扩展。改成给每张卡片挂一个 MutationObserver 数 6 秒内的 DOM 变更次数，结果见第 10 节。要说清楚这个指标的边界：**它只能证伪不能完全证明**——一次「重渲染但输出完全相同」的渲染不产生 DOM 变更，所以它抓不到。React 层面的保证来自设计本身（卡片只接 `id`、自己 `useServer(id)` 订阅、外面套 `memo`；store 的 `applySnapshot` 对没变化的节点保留原对象引用）。

10. **离线时长靠定时器走，不在渲染里读 `Date.now()`。** 渲染期取当前时间是不纯的（React 19 的 `react-hooks/purity` 规则会报错），而且离线节点的快照不再变化，不自己走一下的话这个数字会永远停在掉线那一刻。文案只精确到分钟，30 秒一跳。

## 11. 实现后审查（2026-09-13）

和步骤 05 一样跑了一轮多 agent 对抗性审查：4 个维度（实时链路、前后端契约、React 与渲染性能、界面与可用性）各出一份清单，每条再派一个 agent 专门去推翻。共提出 38 条，完成复核 21 条（确认 15、推翻 6），**另有 17 条因为 API 额度耗尽没跑完复核**——那些我按证据强度自己判，采信了其中带实测数据的几条。

两条高危都在 WebSocket 客户端里，而且都是「点验全绿也照样漏掉」的那种：

1. **指数退避完全没生效，握手失败时每秒重连一次。** `openedAt` 初值为 0 且每次 connect 都不重置，于是 onclose 里的「活够久就把退避归零」判断 `Date.now() - openedAt >= 10s` 有两个恒真分支：连接从来没 open 过时 `Date.now() - 0` 永远成立；上一条连接活过 10 秒之后，这个时间戳就再也不更新了。审查用真实 client.ts 加 WebSocket 桩实测：服务端一直不可达时 15 秒内发起 15 次握手，间隔恒定 1.0 秒；连过再断的场景同样恒定 1 秒。文档 §4.1 要的「1s 起指数退避到 30s」一次都没走到。
   修法是两处：`connect()` 里把 `openedAt` 清零，判断加上 `openedAt !== 0`。顺带给退避加了 ±20% 抖动——服务端恢复的那一刻，所有标签页不该卡在同一毫秒涌进来。
   **修复后实测**：杀掉服务端，握手间隔 2.2 → 3.6 → 8.7 → 18.4 → 33.7 秒。

2. **半死连接检测不出来。** 断线提示的唯一触发条件是 `status !== 'open'`，而 status 只在 onopen / onclose 里翻转。socket 停在 OPEN 但帧不再到达（NAT 超时、笔记本休眠唤醒、VPN 断开、中间的负载均衡悄悄掐链路）时浏览器收不到 close 事件，页面就会拿着冻结的旧值一直显示「在线」——对监控面板来说这是最坏的失败模式：把陈旧数据当实时数据展示。store 里明明有 `ts` 这个现成的新鲜度信号，却只被用来判了个 `> 0`。
   修法：加一个 3 秒周期的看门狗，连续 6 秒没收到帧就 `setStatus('closed')` 并主动关掉连接走重连；`visibilitychange` 里原来的 `|| socket` 短路也一并改掉——socket 还在但帧已过期正是最需要重连的时候。
   **修复后实测**：用 `NtSuspendProcess` 冻住服务端进程（TCP 连接保持、不再发帧），界面在帧停止后 6–9 秒内翻成「连接中断，正在重连」，进程恢复后自动重连。

其余已修（都带实测）：

3. **`isSameServer` 漏了 `traffic` / `ping` / `core`。** 这个函数是整条 memo 链路的地基，用的是手写字段白名单。三个字段现在恒为空所以看不出问题，但步骤 09/13/18 一填上数据，界面就会静默停在旧值且不报任何错。已补进比较，并把注释从「只比会变的那些」改成「每加一个字段必须同步加到这里，否则更新会被静默丢弃」。
4. **`formatBytes` 的进位判断发生在四舍五入之前**，`999999999` 显示成「1000 MB」。改成对取整后的值再判一次。
5. **`formatPrice` 对不在联合类型内的 `cycle` 直接抛异常**，会把整个面板换成错误页（同一函数上一行的货币符号就有 `?? ` 兜底，正好说明这里是漏的）。
6. **速率折线每秒进 2 个点**：采样写在渲染期（`push(ref.current, up)` 直接在组件函数体里），StrictMode 把渲染跑两遍，于是 30 点的窗口实际只有 15 秒，而且 dev 与 prod 行为不一致。挪进 `useEffect(..., [up, down])`。修复后实测点数增长回到每秒 1 个。
7. **固定 4 列导致数值被省略号截断**：1600px 视口下每张卡片只有 276px。改回文档 §4.1 原本写的 `repeat(auto-fill, minmax(300px, 1fr))`，列数由容器宽度自己算。逐档复测 1920/1600/1366/900/600/400 六个宽度，被截断元素数全部为 0。
8. **卡片副文本用 `text.disabled`，深浅两套主题下都达不到 WCAG AA**（实测 1.67:1 / 1.84:1）。提到 `text.secondary`（4.87:1 / 5.65:1），层级靠字号字重拉开。
9. **离线卡片 `opacity: 0.55` 把里面所有文字的对比度一起按比例拉低**，副文本只剩 1.7:1 左右。提到 0.8——真正表达「离线」的是右上角那个红色标签，压暗只是辅助。
10. **首帧到达之前显示「还没有节点」的假空态**。改成三态：没收到过帧 → 「正在加载节点…」；收到帧且真的没节点 → 「还没有节点」；筛没了 → 「没有符合条件的节点」。
11. **页脚多出了分组与全部标签**（文档 §4.4 里没有），长标签会把这一排撑破——`Label` 既不限宽也不换行，实测一个长分组名的 Label 宽 288px 而卡片内容盒只有 236px。改成：页脚只留带宽与价格；分组跟着地区显示在标题下面（`noWrap`）；标签留给工具条筛选。
12. **离线节点同时显示「离线 N 分钟」和「在线 N 天」**，两个「在线」互相打架。页脚那一格改名「运行」（说的是机器开机多久，和连接状态是两回事）；离线时把瞬时速率按 0 传给折线，不再把最后一帧的旧值当实时值显示。
13. **几处文案**：`— 核` → `核数未知`；`离线 不到 1 分钟` → `刚刚离线`；`不限 ∞` → `不限`（两者同义，重复了）。
14. **`SegmentBar` 在 <5% 时整条全空**，和 0% 看起来一样。改成有值就至少点亮一格。
15. **可访问性两处**：`Sparkline` 是纯装饰，加 `aria-hidden`（原来在无障碍树里留下 10 个无名 image 节点）；搜索框没有可见 label，补 `aria-label`（原来只能靠 placeholder 兜底，是 accname 规范里最末一级）。
16. **`Toolbar` 套 memo**：按 CPU 排序时可见顺序每秒都在变，外层 view 跟着每秒重渲染，没必要把 4 个输入控件和十几个菜单项也带上。

**另外修了一个不在审查范围、但我自己在点验时踩到的**：`vite.config.ts` 的 `/api/ws` 代理没有错误处理，后端一重启，代理抛出的 ECONNRESET 会变成未捕获异常，**把整个 dev server 带崩**——调试断线重连时必踩（我第一次跑断线测试就是这么挂的）。加了 `configure` 钩子接住 proxy 与 socket 两层错误。修复后重跑同样的杀服务端测试，Vite 全程存活。

没修、记下来的：

- **卡片被筛掉再出现时，速率折线的历史清零**，要再等 30 秒才填满。历史存在组件本地 ref 里（文档 §7 明确要求不要放 store），跟组件实例同生命周期是这个取舍的必然代价。在搜索框里逐字输入时尤其明显。
- **汇总条没有用 `AnimateCountUp`**（文档 §4.3 要求首帧用）。数值每秒都在变，首帧动画的收益很小，而多引一个动画组件要多担一份闪烁风险。这条是审查指出我漏记的偏离，补记在这里。
- **在线卡片每秒的渲染成本**约 15–20 ms（dev 模式，StrictMode 会翻倍）。这是「每秒刷新」本身的成本，不是 bug；真要压下来得上虚拟列表或降低刷新率，十几台节点的规模不值当。
- **17 条复核没跑完**（API 额度耗尽）。其中我按证据自行采信并修掉的有：长标签撑破卡片、离线对比度、文案问题、SegmentBar 全空、搜索框可访问名、Toolbar 重渲染。剩下的（如「30 天内到期把已过期也算进去」）我改成显式说明而不是改行为——已过期比「还剩 3 天」更需要处理，计进去是对的，加了 tooltip 说明「含已经过期的节点」。
