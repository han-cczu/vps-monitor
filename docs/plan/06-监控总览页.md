# 步骤 06 · 监控总览页

> 阶段 1 · 依赖：05 · 粗估 3–4 天 · 对应设计方案 §4.1、§11.4、§11.5

## 1. 目标

面板首页出现参考截图那样的卡片网格，数据每秒刷新；有汇总条、筛选、排序、搜索；断线有提示。三网延迟、剩余流量、到期等字段先按空态渲染，后续步骤填。

## 2. 范围

**做**：WS 客户端与重连、zustand 实时 store、卡片组件族、汇总条、筛选/排序/搜索、离线态、格式化工具、默认深色主题。

**不做**：详情页（08）、ping 方块真实数据（09）、剩余流量结算（18）。

## 3. 前置条件

步骤 05（snapshot 可用）。

## 4. 实现方案

### 4.1 WS 客户端 `web/src/ws/client.ts`

```ts
export type WsStatus = 'connecting' | 'open' | 'closed';
export function startRealtime(getToken: () => string | null): () => void
```

- URL：`(location.protocol === 'https:' ? 'wss' : 'ws') + '//' + location.host + '/api/ws'`
- `onopen` → 发 `{type:'auth', token}`；收到 `snapshot` → `store.applySnapshot()`
- 断开重连：1s 起指数退避到 30s；`visibilitychange` 回到前台时立即重连
- 在 `AuthProvider` 之后的顶层组件里启动（登录态才连），登出时关闭

### 4.2 实时 store `web/src/store/realtime.ts`

```ts
type State = {
  status: WsStatus; ts: number;
  servers: Record<number, ServerSnapshot>; order: number[];
  applySnapshot(s: Snapshot): void; setStatus(s: WsStatus): void;
};
export const useRealtime = create<State>(...)
export const useServer = (id: number) => useRealtime(s => s.servers[id]);   // 卡片只订阅自己
export const useServerIds = () => useRealtime(s => s.order);
```

`applySnapshot` 用浅比较避免无变化的节点触发重渲染（十几台每秒一次本来也不重，但养成习惯）。类型 `ServerSnapshot` 放 `web/src/types/realtime.ts`，与服务端 snapshot 字段一一对应。

### 4.5 工具 `web/src/utils/format.ts`

`formatBytes(n, {base: 1000|1024})`、`formatRate(bps)`（B/s、KB/s、MB/s）、`formatPercent`、`formatDuration(sec)`（天/小时）、`daysUntil(dateStr)`、`formatPrice(price, currency, cycle)`（`¥99/年`、`$10.79/月`）。`base` 先固定 1000，步骤 20 接设置。

## 6. 验收标准

- [ ] 登录后首页看到所有节点卡片，数值每秒变化；离线节点灰化并显示离线时长
- [ ] 上行/下行小折线随速率变化滚动，30 秒后填满
- [ ] 断开网络：顶部出现"连接中断，正在重连"，数据保留最后一帧；恢复后自动消失
- [ ] 分组/标签筛选、按 CPU 排序、搜索名称即时生效
- [ ] 宽屏 4 列、平板 2 列、400px 宽 1 列，无横向滚动
- [ ] React DevTools Profiler：每秒只有数据变化的卡片重渲染
- [ ] 国旗为本地 SVG；深色/浅色两套主题下文字与进度条都可读

## 7. 风险与注意

- 不要把 30 个采样点放进全局 store（每秒写 store 会让所有订阅者跑一遍 selector），放卡片本地 ref。
- `AnimateCountUp` 只用于汇总条首帧，卡片里每秒动画会闪。
- 截图里的百分比进度条是分段方块而不是连续条，做成 `SegmentBar` 复用于 CPU/内存/磁盘。
