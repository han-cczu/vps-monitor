# 步骤 02 · 服务端基础与认证

## 1. 目标

服务端有配置、有数据库、有登录。前端 starter 的登录页对接真实后端，登录后进入空的 dashboard。

## 2. 范围

**做**：配置加载、SQLite 打开与迁移框架、`users`/`settings`/`audit_log` 三张表、argon2id 密码、JWT 签发校验、登录限速、初始管理员、改密码、审计记录、请求日志、内嵌前端与 SPA 回退。

**不做**：TOTP（步骤 20）、任何业务表。

## 3. 前置条件

步骤 01 完成。

## 4. 实现方案

### 4.1 配置 `server/internal/config`

```go
type Config struct {
    Listen     string        // VM_LISTEN, 默认 ":9000"
    DataDir    string        // VM_DATA_DIR, 默认 "./data"
    PublicURL  string        // VM_PUBLIC_URL, 如 https://panel.example.com；为空时安装命令用请求的 Host 拼
    JWTSecret  string        // VM_JWT_SECRET, 为空则首次启动生成并写入 {DataDir}/jwt.secret（0600）
    TZ         string        // VM_TZ, 默认 Asia/Shanghai
    LogLevel   string        // VM_LOG_LEVEL, 默认 info
}
func Load() (Config, error)   // 只读环境变量，不读文件
```

启动时 `time.LoadLocation(cfg.TZ)`，全局 `clock.Location` 供结算类任务使用。

### 4.2 存储 `server/internal/store`

- `Open(path) (*DB, error)`：DSN `file:{path}?_pragma=journal_mode(WAL)&_pragma=busy_timeout(5000)&_pragma=foreign_keys(1)&_pragma=synchronous(NORMAL)`；`SetMaxOpenConns(1)` 写、另开一个只读连接池给查询（SQLite 单写者，简单起见先用一个 `*sql.DB`，`MaxOpenConns=4`，写操作走事务）。
- 迁移：`migrations/` 目录 `//go:embed`，goose `SetBaseFS` + `Up`。
- `0001_init.sql`：

```sql
CREATE TABLE users (
  id INTEGER PRIMARY KEY, username TEXT NOT NULL UNIQUE,
  password_hash TEXT NOT NULL, totp_secret TEXT, totp_enabled INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL
);
CREATE TABLE settings (key TEXT PRIMARY KEY, value TEXT NOT NULL);
CREATE TABLE audit_log (
  id INTEGER PRIMARY KEY, ts INTEGER NOT NULL, actor TEXT NOT NULL, action TEXT NOT NULL,
  target_type TEXT NOT NULL, target_id TEXT, before TEXT, after TEXT, ip TEXT
);
CREATE INDEX idx_audit_ts ON audit_log(ts);
```

- repo 风格：每张表一个文件 `users.go`、`settings.go`、`audit.go`，方法签名带 `ctx`；`settings` 提供 `Get(key, &v)` / `Set(key, v)`，值 JSON 序列化。

### 4.3 认证 `server/internal/auth`

- 密码：`argon2.IDKey(pw, salt, 3, 64*1024, 2, 32)`，编码为 `$argon2id$v=19$m=65536,t=3,p=2$salt$hash`。
- JWT：HS256，claims `{sub: userID, name, role: "admin", exp: now+12h, iat}`；`Middleware` 读 `Authorization: Bearer`，失败 401 `{message:"unauthorized"}`；把 user 放进 ctx。
- 登录限速 `ratelimit.go`：`map[ip]*bucket`，15 分钟窗口 5 次失败即锁 15 分钟，后台 goroutine 每分钟清理；被锁返回 429 `{message:"too many attempts"}`。
- 初始管理员：启动时 `users` 为空 → 创建 `admin`，密码 16 位随机（大小写数字），**只打印到日志一次**：`initial admin password: ...`。
- handler：
  - `POST /api/auth/sign-in` body `{email, password}`（starter 字段名叫 email，按 username 用）→ `200 {accessToken, user}`；失败 401 `{message:"用户名或密码错误"}`
  - `GET /api/auth/me` → `{user}`
  - `POST /api/auth/password` body `{oldPassword, newPassword}`（新密码 ≥ 10 位）→ 204；写审计
- `user` 对象形状对齐 starter `src/auth/types.ts`：`{ id, displayName, email, photoURL: null, role: "admin" }`。

### 4.4 审计 `server/internal/audit`

```go
func Record(ctx, db, action string, targetType string, targetID string, before, after any)
```

actor 取 ctx 里的用户（系统任务用 `"system"`），ip 取 chi `RealIP`。后续每个写接口都调用。

### 4.5 HTTP 装配 `server/internal/api`

- `NewRouter(deps)`：chi 中间件 `RequestID`、`RealIP`、`Recoverer`、自写 `slog` 访问日志（不记录 `/sub/` 路径的 query 与 token，见步骤 15）、`Compress(5)`。
- 路由分组：`/api/auth/*` 公开；`/api/*` 其余挂 `auth.Middleware`；`/api/agent/*` 在步骤 05 另挂 agent token 校验；剩余全部 → `web.Handler()`：存在的静态文件直接返回（带 `Cache-Control: public, max-age=31536000, immutable` 给带 hash 的 assets），否则返回 `index.html`。
- 统一错误 JSON：`{message: string}`；参数校验错误 400。

### 4.6 前端

- starter 的 JWT 流程直接可用；确认 `auth/context/jwt/utils.ts` 的 `tokenExpired` 里那个 `alert('Token expired!')` 改为 toast + 跳登录页。
- `sections/account/account-change-password.tsx` 接 `POST /api/auth/password`，挂到 `/dashboard/settings/security`。
- 登录页文案改中文，去掉"注册"和第三方登录入口（`auth/view/jwt/sign-in-view.tsx`）。

## 9. 偏离记录

> 实施日期：2026-09-12

### 结构

1. **登录 / me / 改密的 handler 放在 `api` 包，`auth` 包只留纯逻辑**（argon2、JWT、限速、ctx 里的当前用户、初始管理员）。
   文档 §4.3 把 handler 也画在 auth 下，但 audit 要从 ctx 取当前用户（依赖 auth），handler 又要写审计（依赖 audit），放一起就是循环引用。
2. 新增小包 `server/internal/clock` 承载 `VM_TZ` 对应的 `*time.Location`（`clock.Location()` / `clock.Now()`），对应 §4.1 的"全局 clock.Location"。
3. `server/web` 新增 `Handler()`：命中静态文件直接返回（`assets/` 下带 hash 的给一年 immutable 缓存），否则回 `index.html`（`no-cache`）。
   步骤 01 写在 main.go 里的 `spaHandler` 挪过来并删掉；`/api/*` 的 JSON 404 / 405 由 api 包的子路由处理。

### 接口

4. **错误 JSON 统一为 `{message}`**，连带把步骤 01 `/api/*` 404 的 `{error}` 也改了；前端 axios 拦截器改读 `data.message`。
5. **登录请求体前端发 `{username, password}`**，服务端同时接受文档 §4.3 写的 `email` 字段名作为用户名。
   starter 登录表单原本用 `schemaUtils.email()` 校验，`admin` 在客户端就过不去，所以把字段名改成了它的实际含义。
6. 登录成功响应多带一个 `expiresAt`（Unix 秒），前端暂未使用。
7. 限速 429 文案改成中文并带剩余分钟数："尝试次数过多，请 N 分钟后再试"（文档写 `too many attempts`），响应头带 `Retry-After`。
   触发锁定的第 5 次失败仍返回 401，第 6 次起 429；登录成功清零计数。
8. 改密码时"当前密码错误"返回 **400** 而不是 401：前端拦截器对任何 401 都会清会话跳登录页，输错一次旧密码不该被登出。新密码另加 256 字节上限。
9. 登录成功也写审计 `auth.sign_in`（文档只要求改密码写）；登录失败不进审计、只记 `WARN` 日志，避免暴力尝试刷表。
10. 用户名不存在时也跑一次 argon2 校验（`auth.VerifyDummy`），让"用户不存在"与"密码错误"的耗时接近，防止靠响应时间探测用户名。
11. 初始密码用 `WARN` 级别打印（文档没定级别），`VM_LOG_LEVEL=warn` 时也能看到。

### 配置与存储

12. `VM_JWT_SECRET` 至少 32 字节，不足直接启动失败（HS256 短密钥可离线穷举）；自动生成的 `jwt.secret` 是 32 字节随机数的 hex（64 字符）。
    `VM_PUBLIC_URL` 若设置会校验为 http(s) 完整地址并去掉末尾斜杠。
13. SQLite DSN 用"路径 + `?_pragma=...`"而不是文档里的 `file:` URI：Windows 路径里的反斜杠和空格在 URI 里都要转义，
    而 modernc 驱动对两种写法都按连接执行 `_pragma`（有测试断言 `journal_mode=wal`、`busy_timeout=5000`、`foreign_keys=1`）。
14. `audit_log` 的 `before` / `after` 是 SQLite 关键字（触发器语法），建表与查询都加双引号；列名保持与设计方案一致。
15. main.go 匿名导入 `time/tzdata`，静态二进制 / 精简镜像里 `VM_TZ` 也能加载（二进制约 +450 KB）。
16. server 模块已 `go mod tidy`（步骤 01 备注说等依赖用上再 tidy，现在用上了）；尚未使用的 `gorilla/websocket`、`yaml.v3` 用 `go get` 补回为 indirect，留给步骤 03/05。
    agent 模块依赖仍未使用，继续不 tidy。

### 前端

17. 会话到期不是 toast 而是跳 `/auth/sign-in?reason=expired`，登录页据此显示"登录已过期，请重新登录"的提示条——
    `tokenExpired` 里 `window.location.href` 一跳 toast 就没了，做成 toast 用户看不见。
    `tokenExpired` 同时改成只在 sessionStorage 里仍是同一个 token 时才动作，`setTimeout` 延时钳在 2^31-1 ms 内。
18. 改密码页挂在 **`/dashboard/settings/account`**（文档写 `/settings/security`），与步骤 01 已定的 `paths.dashboard.settings.account`
    和账号抽屉入口一致；`/dashboard/settings` 目前直接重定向到它，步骤 20 加 TOTP / 审计 / 备份后再做设置总览。占位页 `pages/dashboard/settings.tsx` 删除。
19. 退出按钮文案改为"退出登录"；登录页左侧副标题改中文。
20. `app.tsx` 补挂 `<Snackbar />`：starter 的根组件没有挂 sonner 的 toast 宿主，
    改密码页的 `toast.success/error` 不挂它一条都不会弹。

### 代码审查后补的加固

写完后做了一轮多视角审查，下面几条是查证属实后改的。

21. **不用 chi 的 `RealIP`，新增 `VM_TRUSTED_PROXIES`。** 文档 §4.5 写的是挂 `RealIP`，但它在 chi v5.3.2 里已被官方标记为弃用：
    它无条件采信 `True-Client-IP` / `X-Real-IP` 和 `X-Forwarded-For` 的**最左**值，而这三个头客户端都能随手伪造，
    Caddy 在前面也不会替你清掉（GHSA-3fxj-6jh8-hvhx 等）。限速和审计的 IP 都来自这里，用它等于限速形同虚设。
    改成默认只认 TCP 连接地址，由 `VM_TRUSTED_PROXIES`（层数或 CIDR 列表）显式声明可信代理后才解析 XFF，解析失败 fail-closed 退回连接地址。
    启动日志会打印实际生效的模式，runbook 里写了上线后怎么用审计表核对一次。
22. **数据目录改用 0700 创建**（原来是 0755）。里面有密码哈希、JWT 密钥，后续还会放 agent token 与订阅凭据，
    在多用户 Linux 主机上 0755 意味着同机任何用户都能读 `vm.db`。
23. **自写 recoverer 替换 chi 的 `Recoverer`。** chi 的只写状态码不写 body，堆栈还是带 ANSI 颜色的纯文本直接打到 stderr，
    与"错误统一 `{message}`"和 slog JSON 日志两条约定都不符。现在 panic 返回 500 `{"message":"服务器内部错误"}`，
    堆栈进 `panic recovered` 的 ERROR 日志（带 `req_id`）；响应已经写出去一部分时只记日志不二次写。
24. **argon2 校验加并发闸**（最多 4 个并发，排队超 5 秒返回 503）。argon2id 每次要吃 64 MiB，
    原先并发多少请求就并发跑多少次校验，几百个并发登录就能把进程 OOM 掉；更要命的是这些请求都在各自 `Fail()` 之前
    通过了 `Locked()` 检查，所以一批并发请求可以整体绕过"5 次"上限。
    拿到槽位后会**再查一次**是否已被锁定，把并发窗口收敛到槽位数。
    实测（20 个并发请求，其中 1 个带正确密码）：修复后 8 个 401、12 个 429，带正确密码的那个也被拦成 429，
    并发内存峰值封顶在 4 × 64 MiB；修复前 20 个会全部跑完 argon2，带正确密码的那个直接登录成功。
25. **改密码接口也限速**：旧密码猜测复用同一个限速器，key 用 `pw:<用户ID>`（不是 IP）。
    token 可能是从别处捡来的，不该让它在这个接口上无限试旧密码。
26. **`rhf-text-field.tsx` 的 `autoComplete` 从硬编码改成默认值**。starter 在 `slotProps.htmlInput` 里把 `autoComplete: 'new-password'`
    写在展开之后，外部传什么都盖不掉，于是登录页的用户名/密码字段无法被浏览器密码管理器正确保存和填充。
    改成默认值放最前、调用方可覆盖，原有"默认关掉自动填充"的行为不变。
27. **侧栏"设置"加 `deepMatch: true`**：`/dashboard/settings` 会重定向到 `/dashboard/settings/account`，
    不开子路径匹配的话这一项永远不会高亮。

### 留给后续步骤

28. 改密码后旧 token 在 12 小时内仍有效（没有 token 版本号 / 黑名单）。单管理员可接受；
    要严格失效可在步骤 20 加 `password_changed_at` 并在中间件里比对 `iat`。眼下的应急手段是换掉 `jwt.secret`（runbook 有）。
29. `VM_TRUSTED_PROXIES` 只解决"谁是客户端"，不解决"谁能连上来"。步骤 07 部署时仍要用防火墙/安全组保证只有 Caddy 能访问监听端口，
    并把这个变量一起写进 compose。
