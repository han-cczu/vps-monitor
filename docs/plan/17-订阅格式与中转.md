# 步骤 17 · 订阅格式与中转

> 阶段 4 · 依赖：16 · 粗估 3 天 · 对应设计方案 §10.2、§10.3、§4.5 高级、§9.4 合并规则 · 完成即里程碑 **M4**

## 1. 目标

补齐 sing-box 与 URI 两种订阅格式；节点级高级 JSON 可在页面编辑并预检；提供"中转到另一节点"的生成助手；订阅模板可在设置页编辑。

## 2. 范围

**做**：`format=singbox|uri`、高级 JSON 编辑器与预检接口、中转出站生成助手（含中转专用订阅用户）、订阅模板设置页、安全组待放行端口提示。

**不做**：Clash 规则集市场之类的扩展。

## 3. 前置条件

步骤 16。

## 4. 实现方案

### 4.1 sing-box 格式 `proxy/sub/singbox.go`

输出 `{"outbounds":[...]}`（只给 outbounds，用户自己的 sing-box 配置用 `outbound_providers` 或手工合并；后续若客户端普遍支持远程 outbound 列表再调整）。四协议：

- vless：`{type, tag, server, server_port, uuid, flow:"xtls-rprx-vision", tls:{enabled:true, server_name, utls:{enabled:true, fingerprint:"chrome"}, reality:{enabled:true, public_key, short_id}}}`
- shadowsocks：`{type, tag, server, server_port, method, password:"服务端PSK:用户PSK"}`
- hysteria2：`{type, tag, server, server_port, password, obfs:{type:"salamander", password}, tls:{enabled:true, server_name: sni, alpn:["h3"], certificate:[PEM 行数组]}}`
- tuic：`{type, tag, server, server_port, uuid, password, congestion_control, udp_relay_mode:"native", tls:{enabled:true, server_name, alpn:["h3"], certificate:[...]}}`

`tag` 同 Clash 的 `name`。`Content-Type: application/json`。

### 4.2 URI 格式 `proxy/sub/uri.go`

按设计 §10.3 四条模板拼装，`#` 后名称 URL 编码；每行一条，整体 base64（标准）；`Content-Type: text/plain`。TUIC 用 `allow_insecure=1`（无 pin），在订阅对话框里加一句说明。

### 4.3 高级 JSON

- 服务端：`PUT /api/servers/{id}/advanced { extra_json }`：先 `json.Valid`，再以当前入站渲染一遍 `Render + Check`（不落修订，纯校验），失败返回 400 与 `sing-box check` 的 stderr；通过才保存并 `NodeChanged`。`POST /api/servers/{id}/advanced/check` 同样逻辑但不保存（编辑器"校验"按钮）。
- 前端 `sections/proxy/detail/advanced-json.tsx`：`Dialog` 内等宽多行 `TextField`（或 `textarea`）+ 行号可省；按钮：校验、保存、恢复为 `{}`；右侧折叠面板"示例"给两段：自定义 `dns`、`route.rules` 加规则；错误信息以 `Alert` 显示原文。

### 4.4 中转助手

目标：在节点 A（如深圳）加一个出站指向节点 B（如香港）的入站，并把 A 的默认出口改为 B。

- 服务端 `POST /api/servers/{id}/advanced/relay { target_server_id, target_inbound_id }`：
  1. 查目标入站（限 `shadowsocks` 或 `vless`，QUIC 类中转效果差不提供）
  2. 找或建"中转专用订阅用户" `relay:{A}->{B}`（`subscribers` 加列 `kind TEXT DEFAULT 'user'`，值 `relay`；列表页默认隐藏 `relay` 类型；不限额、不到期；迁移 `0008_relay.sql`），并分配到目标入站
  3. 生成出站 JSON（同 4.1 的客户端写法，`tag: "relay-{B名}"`）与 `route.final = "relay-{B名}"`，**合并**进 A 的 `extra_json`（已存在同 tag 则替换）
  4. 走校验后保存 → A、B 两个节点都 `NodeChanged`
- 前端在高级 JSON 对话框加"中转到其它节点"按钮：选节点、选入站，确认后填充并提示"A 的所有出口流量将经由 B"。删除中转 = 手动删掉出站与 final（对话框提供"移除中转"按钮做同样事情）。
- 中转流量统计：B 上以 `sub-{relayId}` 计数，详情页按节点分账可见；总览不计入"人"的用量。

### 4.5 订阅模板设置页

`settings/subscription`：Clash 模板 `textarea`（等宽）、占位符说明、"恢复默认"、保存前服务端做占位替换 + YAML 解析校验；同页放 `enforce.count_mode` 下拉（步骤 16 提到）。

### 4.6 待放行端口提示

核心状态卡（步骤 14）新增"安全组待放行"区：把该节点全部启用入站的端口按 `tcp/udp` 列出并可复制为 `443/tcp, 8388/tcp, 8388/udp, 8443/udp`；防火墙为 `none` 时高亮。纯前端计算。

### 4.7 订阅对话框补齐

Tabs 增加 sing-box、URI；每项附一句适用客户端说明；URI 项下注明 TUIC 无证书校验。

## 5. 接口与数据

| 类型 | 内容 |
|---|---|
| 公开 | `GET /sub/{token}?format=singbox|uri` |
| REST | `POST /api/servers/{id}/advanced/check`、`POST /api/servers/{id}/advanced/relay`、`PUT /api/settings`（模板、count_mode） |
| 表 | `subscribers.kind` |
| settings | `sub.clash_template`（可编辑）、`enforce.count_mode` |

## 6. 验收标准

- [ ] `format=singbox` 输出能被 sing-box 客户端合并使用（至少 `sing-box check` 通过一份把它嵌入的客户端配置）；四个出站连通
- [ ] `format=uri` 用 Shadowrocket 或 NekoBox 导入，VLESS / SS / HY2 三条连通（TUIC 视客户端）
- [ ] 高级 JSON 写错字段 → 校验按钮返回 sing-box 的错误原文；写对后保存并下发
- [ ] 中转助手：深圳节点选香港 SS 入站 → 保存后从深圳节点 `curl ipinfo.io` 出口 IP 为香港；香港节点详情页分账里出现 `relay:` 用户
- [ ] 移除中转后出口恢复
- [ ] 模板改坏（YAML 缩进错）保存被拒并提示；恢复默认可用
- [ ] 待放行端口列表与实际入站一致

## 7. 风险与注意

- 中转链路里 A 的所有流量（含 agent 到面板的连接）都会经 B 出去吗？——不会：sing-box 只处理进入其入站的流量，系统自身流量不经过它。但要在 UI 里说明"仅代理流量经中转"。
- `extra_json` 是管理员的自由区，渲染冲突（如重复 tag）由预检兜底，报错要把 sing-box 原文透出来。
- 订阅格式越多，客户端差异越多；验证结果继续记到 `docs/verify/`。
