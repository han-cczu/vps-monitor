# 步骤 03 · 节点管理

> 阶段 1 · 依赖：02 · 粗估 2 天 · 对应设计方案 §4.3、§8.2、§7.4

## 1. 目标

能在面板里添加节点、拿到 agent token 与一键安装命令；节点列表与编辑表单可用。表单包含账单与流量套餐字段（结算逻辑在步骤 18，这里只存）。

## 2. 范围

**做**：`servers`、`server_host_info` 两张表；CRUD 接口；token 生成与重置；安装命令拼装；`/install.sh` 与 `/agent/{file}` 的静态托管位置；前端节点列表页与表单。

**不做**：在线状态（步骤 05 才有，这里显示"未连接"）、实际的 install.sh 内容（步骤 04）。

## 3. 前置条件

步骤 02 完成。

## 4. 实现方案

### 4.1 迁移 `0002_servers.sql`

```sql
CREATE TABLE servers (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL, region TEXT NOT NULL DEFAULT '', group_name TEXT NOT NULL DEFAULT '',
  tags TEXT NOT NULL DEFAULT '[]', sort_order INTEGER NOT NULL DEFAULT 0,
  token_hash TEXT NOT NULL UNIQUE, public_host TEXT NOT NULL DEFAULT '',
  price REAL NOT NULL DEFAULT 0, currency TEXT NOT NULL DEFAULT 'CNY',
  billing_cycle TEXT NOT NULL DEFAULT 'month',        -- month | quarter | year | once
  expire_at TEXT, auto_renew INTEGER NOT NULL DEFAULT 0,
  traffic_limit INTEGER NOT NULL DEFAULT 0, traffic_reset_day INTEGER NOT NULL DEFAULT 1,
  traffic_mode TEXT NOT NULL DEFAULT 'max',           -- out | in | sum | max
  bandwidth_label TEXT NOT NULL DEFAULT '', note TEXT NOT NULL DEFAULT '',
  created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL
);
CREATE TABLE server_host_info (
  server_id INTEGER PRIMARY KEY REFERENCES servers(id) ON DELETE CASCADE,
  hostname TEXT, os TEXT, kernel TEXT, arch TEXT, cpu_model TEXT, cores INTEGER,
  mem_total INTEGER, disk_total INTEGER, boot_time INTEGER,
  ipv4 INTEGER, ipv6 INTEGER, public_ip TEXT, agent_version TEXT, updated_at INTEGER
);
```

### 4.2 服务端

- `store/servers.go`：`List`、`Get`、`Create`、`Update`、`Delete`、`FindByTokenHash`、`UpdateTokenHash`；`store/hostinfo.go`：`Upsert`、`Get`。
- token：`crypto/rand` 32 字节 → base64url（43 字符）；只存 `sha256` hex。创建与重置接口把明文放在响应里返回一次。
- 校验：`name` 1–64；`region` 空或 ISO 3166-1 alpha-2（大写两字母）；`tags` ≤ 10 个、每个 ≤ 16 字；`billing_cycle`/`traffic_mode` 枚举；`traffic_reset_day` 1–31；`expire_at` `YYYY-MM-DD` 或 null；`public_host` 空或合法 host/IP。
- 安装命令拼装 `api/servers.go: installCommand(publicURL, token)`：

```
curl -fsSL {PUBLIC_URL}/install.sh | bash -s -- --server {wss://host}/api/agent/ws --token {token}
```

`PUBLIC_URL` 为空时用请求的 `Host` 与协议推断（开发环境）。
- 静态托管：`GET /install.sh`、`GET /agent/{file}` 从 `{DataDir}/agent/` 读（步骤 07 的镜像会把 CI 产物放进去；开发时手动 `make build-agent` 后拷）。文件名白名单 `^vps-agent-linux-(amd64|arm64)$`、`install.sh`、`uninstall.sh`。
- 列表接口返回值预留 `online: false, last_seen: null, host: {...}` 字段，步骤 05 填。
- 全部写接口记审计（`server.create/update/delete/token_reset`），`before/after` 里不含 token。

### 4.3 前端 `sections/servers/`

- `list/servers-list-view.tsx`：`CustomDataGrid`，列：名称（带国旗）、地区、分组、标签（`Label`）、状态（占位"未连接"）、到期、操作（编辑、token、删除）。顶部"新增节点"。
- `form/server-form.tsx`：`Dialog` 内 `Tabs`：
  - 基础：名称、地区（下拉：常用国家码 + 自由输入）、分组、标签（多值输入）、排序、备注
  - 接入：公网地址 `public_host`；（编辑态）"重置 token"按钮
  - 账单：价格、货币（CNY/USD/HKD/EUR…）、周期、到期日（`DatePicker`）、自动顺延
  - 套餐：流量上限（数字 + 单位 GB/TB 选择，存字节）、重置日、统计模式（四选一，带一句说明）、带宽标签
  RHF + zod，字段校验与后端一致。
- `token-dialog.tsx`：创建成功或重置后弹出，显示 token 与一键安装命令，复制按钮，提示"只显示一次"。
- `api/servers.ts`：`useServers()`（SWR）、`createServer`、`updateServer`、`deleteServer`、`resetToken`。
- 路由：`/dashboard/servers`、`/dashboard/servers/new`（可用 dialog 代替独立页）、`/dashboard/servers/:id/edit`。

## 5. 接口与数据

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/servers` | 列表，含 `online/last_seen/host`（占位） |
| POST | `/api/servers` | 创建 → `{server, token, installCommand}` |
| GET | `/api/servers/{id}` | 单个 |
| PUT | `/api/servers/{id}` | 更新 |
| DELETE | `/api/servers/{id}` | 删除（级联 host_info；后续表也级联） |
| POST | `/api/servers/{id}/token` | 重置 → `{token, installCommand}` |
| GET | `/install.sh`、`/agent/{file}` | 静态托管（公开，无鉴权） |

## 9. 偏离记录

> 实施日期：2026-09-12

### 结构

1. **请求体校验单独放 `api/servers_input.go`**，`api/servers.go` 只留 handler 与 DTO（文档 §8 产出物只写了 `api/servers.go`）。
   十六个字段的规范化与校验有两百多行，和 handler 挤在一起读不动。
2. **token 的生成与哈希放 `auth/agenttoken.go`**（`NewAgentToken` / `HashAgentToken`），不放 api 包：
   步骤 05 的 agent hub 要用同一个哈希函数验票，auth 是两边都能引的纯逻辑包。
3. store 按既有风格拆成 `servers.go` 与 `hostinfo.go` 两个文件（与文档一致）。

### 接口

4. **节点资源的 JSON 字段用蛇形**（`public_host`、`expire_at`、`install_command`），文档 §5 写的是 `{server, token, installCommand}`。
   设计方案 §7.3 的 WS 快照本来就是蛇形，步骤 06 的卡片和这里的列表共用一套前端类型，两处不该一个驼峰一个蛇形。
   `/api/auth/*` 里的 `accessToken`、`displayName` 保持不变——那是对齐前端 starter 的既有结构，已写进 `protocol.md` §3.1。
5. 创建返回 **201**（文档没写状态码），删除返回 204。
6. **节点不存在统一 404 `{"message":"节点不存在"}`**，`{id}` 不是正整数时同样按 404 处理（不是 400）：
   对调用方来说"这个 URL 没有对应资源"是一回事。
7. **PUT 是全量覆盖**：没传的字段按缺省值落库（`currency`→`CNY`、`billing_cycle`→`month`、`traffic_mode`→`max`、`traffic_reset_day`→`1`）。
   前端表单每次都全量提交，不做 PATCH 语义。
8. 规范化比文档多做了几件事：`region` / `currency` 小写自动转大写；`tags` 去空白、丢空串、按原顺序去重；
   `expire_at` 用 `time.Parse` 校验后**回写成标准格式**（`2026-1-2` 会被存成 `2026-01-02`），避免库里两种写法并存。
   校验消息全是中文，直接进 400 的 `message` 给用户看。
9. `currency` 的校验是"三位 A–Z"而不是枚举（文档 §4.3 只举了 CNY/USD/HKD/EUR）：前端给常用下拉，后端不拦冷门币种。
10. **`/agent` 与 `/agent/`（没带文件名）也显式挂到同一个处理器**，回纯文本 404。
    不挂的话它们会落到 SPA 回退，给 `curl | bash` 返回一整页 HTML。
11. 静态下载用 `http.ServeContent`：带 `Last-Modified`、支持 Range 续传（agent 二进制几十 MB），`Cache-Control: no-cache`
    ——文件名固定而内容会随版本变，不能长缓存。404 是纯文本。
12. **`X-Forwarded-Proto` 只在 `VM_TRUSTED_PROXIES` 非空时才采信**，用来推断安装命令里的 `https/wss`。
    直连时这个头和 `X-Forwarded-For` 一样可以随手伪造（步骤 02 偏离记录 21 的同一个理由）。它只影响给管理员看的命令文本，不参与鉴权。

### 数据

13. **`server_host_info` 用一列 `public_ip`**，设计方案 §8.2 写的是 `public_ipv4` / `public_ipv6`。
    步骤 04 的 agent 只探测 IPv4 / IPv6 的**可达性**（两个布尔列 `ipv4` / `ipv6`），
    公网地址是步骤 05 由服务端从 agent 的连接地址记的，只会有一个。本步骤文档 §4.1 的 SQL 也是这么写的，按它实现。
14. 加了索引 `idx_servers_sort(sort_order, id)`——列表默认按这两列排。
15. `UpsertHostInfo` 的 `updated_at` 由 store 自己填当前时间，调用方传什么都被覆盖。

### 前端

16. **新增 / 编辑用同一个 Dialog**（文档 §4.3 允许），没有 `/dashboard/servers/new` 与 `/:id/edit` 两条路由——
    `paths.dashboard.servers` 里的 `new` / `edit` 先留着，步骤 14 做节点详情页时再决定要不要独立页。
17. 列表用 `@mui/x-data-grid` 的 `DataGrid` + 主题里默认开启的工具栏；starter 的 `components/custom-data-grid`
    只提供工具栏零件和 `CustomGridActionsCellItem`，没有叫 `CustomDataGrid` 的整体组件。
    「新增节点」按钮放在 `CustomBreadcrumbs` 的 `action` 上，与 starter 其它列表页一致。
18. **数值字段用 `z.coerce`，`useForm` 用三个泛型** `<z.input, unknown, z.infer>`：
    starter 的 `RHFTextField` 对 `type="number"` 的处理是"输入过程中存字符串、blur 后才转成数字"，
    schema 不做 coerce 的话敲字的中途就会报"需要数字"。
19. 四个 Tab 的字段**始终挂载**（只切 `display`），提交校验失败时自动跳到第一个出错的 Tab——
    否则用户点了保存却没反应，错误红字藏在没显示的 Tab 里。
20. 流量上限按 **1024 进制**（GB = 2^30、TB = 2^40）在前端换算成字节，服务端只认字节。
    商家标称的 "1 TB" 有时是 10^12，差 10%——面板内部统一按 1024，和容量显示口径一致。
21. 列表比文档 §4.3 多了「价格」「流量」两列：账单与套餐两个 Tab 填的东西，列表里一眼看不到就得逐个点开。
22. `ConfirmDialog` 的取消按钮文案从 starter 遗留的 `Cancel` 改成「取消」（组件本身是公共件，这里顺手中文化）。
23. 共享类型放 `src/types/server.ts`（步骤 06 的实时快照要复用同一套字段名）；
    地区 / 货币 / 周期 / 统计模式的选项表放 `sections/servers/constants.ts`，地区用 freeSolo 的 Autocomplete，支持填下拉里没有的国家码。
24. 图标只能用 starter 离线图标集 `components/iconify/icon-sets.ts` 里已有的名字（不在表里的 tsc 直接报错），
    所以「重置 token」用的是 `ic:round-vpn-key`。

### 留给后续步骤

25. `online` / `last_seen` / `host` 是占位：`online` 恒 `false`、`last_seen` 恒 `null`，
    `host` 只有在 `server_host_info` 有行时才非空（本步骤没有写入者）。步骤 05 接上 hub 后才会动。
26. 列表是 DataGrid 的客户端分页，没做服务端分页与排序。节点数上千再说。

    在那之前 `/install.sh` 一直返回 404（已在 runbook 注明）。
28. 删除节点目前只级联到 `server_host_info`；后续步骤的表建好后，级联范围会自动扩大（都挂 `ON DELETE CASCADE`），
    删除确认的文案已经按最终形态写了。

### 验收情况

服务端与数据层用**真实二进制**跑了一遍完整流程（`go build` 后起在 127.0.0.1:9111，脚本走 HTTP + 直接查 SQLite）：
登录、创建（中文字段、`region`/`currency` 归一、tags 去重、四组字段回显）、安装命令拼装、
token 只出现一次（列表与详情响应体里搜不到、库里是 64 位 sha256）、六种非法值各自被 400 拦下并带中文提示、
更新与清空到期日、重置 token（旧哈希不再匹配、新命令带新 token）、
`/install.sh` 未放文件时纯文本 404 / 放了文件后 200 且 Content-Type 正确、`/agent/vm.db` 与目录穿越写法 404、
`/agent/vps-agent-linux-amd64` 不带鉴权可下载、host info 级联删除、四条审计记录齐全且不含 token 与哈希——**全部通过**。
另有单测覆盖 store（CRUD、排序、token 唯一与替换、级联、upsert）、
HTTP 全流程（鉴权、归一化、token 一次性、校验表驱动、审计、静态托管白名单与目录穿越）、
`NewAgentToken` / `HashAgentToken`。`go vet` 与 `go test ./server/...` 全绿。

前端：`tsc --noEmit`、`eslint src/**`、`prettier --check`、`vite build` 四项通过；
dev 环境（Vite 8080 → Go 9000）经代理走通了登录、创建、列表。

**没验的是浏览器里的交互**：token 弹窗与复制按钮、删除的二次确认框、四个 Tab 的填写与回显、
表单校验的红字提示、手机宽度下 Tab 是否可横向滚动。本机这一轮没有可用的浏览器自动化工具，
不能替这几条打勾——第 6 节最后一条按原样留空，其余几条标了"待点验"。
开着 `make dev-server` + `make dev-web` 打开 http://localhost:8080/dashboard/servers 过一遍即可。
