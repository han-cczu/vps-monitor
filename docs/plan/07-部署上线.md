# 步骤 07 · 部署上线

> 阶段 1 · 依赖：06 · 粗估 1–2 天 · 对应设计方案 §12 · 完成即里程碑 **M1**

## 1. 目标

面板以 Docker 形式跑在香港节点上，HTTPS 可用；agent 二进制与安装脚本由镜像自带；有发布流水线、备份脚本与 runbook。

## 2. 范围

**做**：多阶段 Dockerfile、docker-compose、Caddyfile、发布 CI（镜像 + agent 二进制）、首启流程、备份脚本、runbook 初版。

**不做**：sing-box 相关（10）、agent 自动更新（20）。

## 3. 前置条件

步骤 06；一台有域名解析的 VPS（香港），80/443 可达。

## 4. 实现方案

### 4.1 Dockerfile（仓库根 `deploy/Dockerfile`）

```dockerfile
# 1. 前端
FROM node:24-alpine AS web
WORKDIR /src/web
COPY web/package*.json ./
RUN npm ci
COPY web/ .
RUN npm run build

# 2. Go（server + agent 两架构）
FROM golang:1.26-alpine AS go
WORKDIR /src
COPY go.work go.work.sum ./
COPY proto/ proto/
COPY agent/ agent/
COPY server/ server/
COPY --from=web /src/web/dist server/web/dist
ARG VERSION=dev
RUN CGO_ENABLED=0 go build -trimpath -ldflags "-s -w -X main.version=$VERSION" -o /out/server ./server/cmd/server \
 && CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -ldflags "-s -w -X main.version=$VERSION" -o /out/agent/vps-agent-linux-amd64 ./agent/cmd/agent \
 && CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -ldflags "-s -w -X main.version=$VERSION" -o /out/agent/vps-agent-linux-arm64 ./agent/cmd/agent \
 && cp agent/install.sh agent/uninstall.sh /out/agent/

# 3. 运行
FROM gcr.io/distroless/static-debian12
COPY --from=go /out/server /app/server
COPY --from=go /out/agent /app/agent-dist
ENV VM_LISTEN=:9000 VM_DATA_DIR=/data
VOLUME /data
EXPOSE 9000
ENTRYPOINT ["/app/server"]
```

服务端启动时若 `{DataDir}/agent/` 为空或版本文件旧于 `/app/agent-dist/VERSION`，把 `/app/agent-dist/*` 复制过去（步骤 03 的静态托管读 `{DataDir}/agent/`）。这样升级镜像即升级可下载的 agent。

### 4.2 Compose 与 Caddy（`deploy/`）

`docker-compose.yml` 与 `Caddyfile` 按设计方案 §12.1；补充：

- `.env.example`：`PANEL_DOMAIN`、`VM_JWT_SECRET`、`VM_TZ`
- Caddyfile 可选片段（IP 白名单）：

```
panel.example.com {
    @allowed remote_ip 1.2.3.4/32 5.6.7.0/24
    handle @allowed { reverse_proxy server:9000 }
    handle { respond 403 }
    log {
        output file /data/access.log
        format json
    }
}
```

- 日志脱敏：`/sub/*` 的 query 不进日志——Caddy 用 `log { format filter { request>uri query { delete token } } }`，步骤 15 上线订阅时补齐。

### 4.3 发布 CI `.github/workflows/release.yml`

- 触发：推 tag `v*`
- 构建镜像（`docker/build-push-action`，`--build-arg VERSION=$TAG`，平台 `linux/amd64`；面板主机若是 arm 再加），推 GHCR
- 同时把 `agent` 两架构二进制与脚本作为 GitHub Release 资产上传（方便不走面板直接下载）

### 4.4 首启与运维脚本

- `deploy/backup.sh`：`docker compose exec -T server /app/server backup /data/backup/vm-$(date +%F).db`（服务端实现 `backup` 子命令，用 `VACUUM INTO`），保留 14 天；`crontab` 示例每日 03:00
- `deploy/restore.md`：停 server → 替换 `data/vm.db` → 起
- `docs/runbook.md` 初版：安装、升级（`docker compose pull && up -d`）、回滚（指定旧 tag）、看日志、初始密码找回（`docker compose logs server | grep initial`）、重置管理员密码（`/app/server reset-password admin` 子命令）

### 4.5 服务端子命令

`server`（默认运行）、`server backup {path}`、`server reset-password {username}`（打印新随机密码）、`server version`。

## 5. 接口与数据

无新增 API。新增子命令与环境变量见上。

## 6. 验收标准

- [ ] 在干净的香港 VPS 上：装 Docker → `git clone`/下载 `deploy/` → 填 `.env` → `docker compose up -d`，15 分钟内 `https://panel.example.com` 可登录
- [ ] Caddy 自动签证书；HTTP 自动跳 HTTPS；WS（`/api/ws`、`/api/agent/ws`）经 Caddy 正常
- [ ] 用面板生成的安装命令在四台节点装 agent，全部在线
- [ ] `docker compose pull && up -d` 升级后数据保留、agent 自动重连
- [ ] `backup.sh` 生成的 db 文件可用 `sqlite3` 打开且表齐全；按 restore.md 恢复成功
- [ ] `server reset-password admin` 可用
- [ ] 镜像大小小于 60 MB；容器内存占用小于 100 MB

## 7. 风险与注意

- distroless 无 shell，排障用 `docker compose logs`；确实需要进容器时临时换 `alpine` 基础镜像。
- Caddy 数据卷（证书）要持久化，否则重启后重新签发可能触发 Let's Encrypt 限流。
- 面板若放在国内机房，域名需备案；本方案放香港。
