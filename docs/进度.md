### 步骤 08 · 历史曲线 —— 验收 7/7，2026-09-13 完成

- **聚合链路**：秒级上报不落库，先在内存里按分钟聚合（平均 / 峰值 / 取最后一条三类语义），每分钟第 2 秒写一次；每小时第 5 分钟降采样成小时行并清理过期数据；启动时补跑停机期间漏掉的小时行。落库量降到 1/60。
- **两张表**：`metrics_minute`（默认留 7 天）、`metrics_hour`（默认留 365 天），`(server_id, ts)` 复合主键 + `WITHOUT ROWID`，随节点级联删除。保留期可改 `settings`，填非法值会被忽略。
- **API**：`GET /api/servers/{id}/history?range=1h|24h|7d|30d`——前两档读分钟表、后两档读小时表；缺失的点不补零。
- **详情页** `/dashboard/servers/:id`：实时卡片（复用总览页的）+ 主机信息面板 + 时间窗切换 + 五张曲线（CPU 平均与峰值、内存/Swap、磁盘、网速、连接数与进程数）。
- **一个容易踩的坑**：降采样里「取区间最后一行」不能依赖 SQLite 的「裸列跟随 min/max」——那条规则在有多个 `MAX()` 时是未定义的，真按那样写磁盘用量会变成「CPU 峰值最高那一分钟的值」。用显式 JOIN 实现，并有测试专门卡这一点。
- **本步没跑多 agent 审查**（API 额度耗尽），改为自己过高风险点 + 对着真库写 13 个测试。记在 08 文档偏离 12。
