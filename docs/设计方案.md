# VPS 监控与节点管理系统 · 设计方案

> 版本 v1.0 · 2026-09-12 · 状态：设计已确认，待开工
>
> 一句话：一个自托管面板，左手监控十几台 VPS 的实时状态、账单与流量，右手在这些 VPS 上集中部署 sing-box 节点、管理订阅用户与限额，并输出一个聚合所有节点的 Clash 订阅。

## 1. 目标与范围

### 1.1 目标

1. **监控**：十几台 VPS 的实时状态（CPU、内存、磁盘、负载、网速、累计流量、三网延迟）、历史曲线、账单与到期倒计时、流量套餐余量、告警通知。
2. **节点管理**：在这些 VPS 上一键安装 sing-box，集中管理入站协议；管理"订阅用户"（人）及其流量限额与到期；输出聚合订阅——一个链接包含该用户在所有节点上的全部入站。

### 1.2 范围外

- 远程终端、任意命令执行（agent 只接受白名单指令，见 5.4）
- 需要域名与证书的协议
- 按用户限速、按用户限设备数
- 多管理员、多租户、注册
- Windows 节点 agent（面板在 Windows 上开发没问题，agent 只出 Linux 版）

### 1.3 参考对象

- **Komari**：卡片信息结构（V4/V6 标签、四项资源、上下行与累计流量、剩余流量进度条、三网延迟方块、在线/到期天数、带宽与价格标签）。其"已用流量 = max(出站, 入站)"与本方案默认模式一致。
- **3x-ui**：入站/客户端/限额/到期/订阅这套功能，但 3x-ui 是每台机一个面板，本方案是一个面板管所有节点。

## 2. 总体架构

### 2.1 组件

```
 每台 VPS（十几台）                        面板主机（建议放香港节点）                           浏览器（仅管理员）
┌──────────────────────────┐           ┌────────────────────────────────────────────┐
│ vps-agent（Go 单文件，root）│           │ vps-server（Go 单文件，内嵌前端）              │
│  ├ collector  秒级采集     │ ─WSS 上报─▶│  ├ hub/agent    认证、心跳、内存最新状态        │ ─WSS 每秒快照─▶ 监控总览
│  ├ ping       三网延迟     │ ◀─下发配置─│  ├ hub/client   每秒广播给浏览器               │ ◀─REST────────  详情页 / 管理页
│  └ corectl    管 sing-box  │           │  ├ store        SQLite（配置 + 时序聚合）       │
│        │                  │           │  ├ traffic      节点流量结算（账期、模式）        │
│  sing-box（自编译）        │           │  ├ proxy        渲染 / 密钥 / 证书 / 订阅 / 限额 │ ◀─GET /sub/{token}─ Clash 客户端
│   入站 vless·ss·hy2·tuic   │           │  ├ corefiles    托管 sing-box 二进制            │
│   v2ray_api 127.0.0.1:10085│           │  ├ alert        告警规则与通知                  │ ──▶ Telegram / Webhook
└──────────────────────────┘           │  └ auth         JWT + TOTP、审计               │
                                       └────────────────────────────────────────────┘
```

三个独立部分：**Agent（采集 + 受控执行）→ Server（汇聚、存储、渲染、推送）→ Web（展示、管理）**。Agent 主动出站连接 Server，VPS 不需要开任何管理端口；只有 sing-box 的入站端口按需对外开放。

### 2.2 三条数据流

1. **监控流**：agent 每秒采集 → WSS 上报 → Server 更新内存里的"最新状态" → 每秒序列化一次广播给所有浏览器；同时在内存按分钟聚合，每分钟落库一行。
2. **控制流**：管理员改入站/用户 → Server 重新渲染该节点的"期望状态"（sing-box 版本 + 完整 `config.json`，带修订号）→ 通过同一条 WSS 下发 → agent 校验、应用、失败回滚 → 上报实际状态。
3. **订阅流**：Clash 客户端定时 `GET /sub/{token}` → Server 按该用户的分配关系生成 YAML，并在响应头带上用量与到期。

### 2.3 部署拓扑要点

- 面板放**香港**节点：国内、海外节点连它都没问题。放深圳阿里云则域名走 80/443 需 ICP 备案。
- Hysteria2 / TUIC 是 **UDP/QUIC**，云安全组与主机防火墙都要放 UDP；国内出口对 QUIC 经常限速，深圳节点建议只开 Reality 和 SS。
- 面板同时是 sing-box 二进制的分发点，国内节点不需要访问 GitHub。

## 3. 技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| Agent | Go，`CGO_ENABLED=0` 静态编译 linux/amd64 + arm64；`gopsutil` 采集、`pro-bing` ICMP、`coder/websocket` | 单文件、零依赖、常驻 10–20 MB；十几台机器上装 Python 依赖是灾难 |
| Server | Go；`chi` 路由、`gorilla/websocket`、`modernc.org/sqlite`（纯 Go 驱动，WAL 模式） | 单二进制内嵌前端；十几台节点每天几万行，SQLite 绰绰有余 |
| 时序存储 | SQLite 分钟表 + 小时表 | 超过百台再换 VictoriaMetrics，store 层留接口 |
| 前端 | Minimal UI **starter** v7.7.0：React 19、MUI 9、react-router 7、SWR、react-hook-form + zod、ApexCharts、framer-motion | 后台壳（侧栏、深色模式、表格、表单、登录）现成；缺的组件从完整版拷 |
| 代理核心 | sing-box，钉住一个版本，自编译（含 `with_v2ray_api`） | 一个核心覆盖四个协议；每用户流量统计需要 V2Ray API |
| 反向代理 | Caddy | 自动 HTTPS，WebSocket 直通 |
| 部署 | Docker Compose（server + caddy）；agent 用 systemd | |
| 通知 | Telegram Bot、通用 Webhook | |

## 4. 功能规格

### 4.1 监控总览（卡片网格）

每台节点一张卡，宽屏 4 列、平板 2 列、手机 1 列。字段与来源：

| 卡片元素 | 数据 | 来源 |
|---|---|---|
| 国旗、名称 | `region`、`name` | 后台手填 |
| V4 / V6 标签 | 是否有 IPv4 / IPv6 出网 | agent 启动时分别用 v4、v6 连一次外网探测 |
| CPU %、核数 | `cpu`、`cores` | agent |
| 内存 %、已用/总量 | `mem_used`、`mem_total` | agent |
| 磁盘 %、已用/总量 | 根分区（或指定挂载点） | agent |
| 负载 | `load1` | agent |
| 上行 / 下行速率 + "实时"小折线 | 网卡计数器差值 ÷ 秒 | agent 算速率；前端本地保留最近 30 个点画线 |
| 出站 / 入站累计 | 网卡累计字节 | agent 上报累计值，Server 算差值累加到账期 |
| 剩余流量 + 进度条 | 套餐上限、重置日、统计模式 | 后台配置 + Server 结算（4.9） |
| 三网延迟、丢包、方块 | 到深圳电信/联通/移动目标的 ping | 后台配置目标，agent 定时执行（4.4） |
| 在线 N 天 | `uptime` | agent |
| 到期 N 天 | `expire_at` | 后台手填（4.8） |
| 带宽、价格标签 | `bandwidth_label`、`price`、`cycle` | 后台手填 |

页面行为：顶部汇总条（在线/总数、总上下行速率、本月总流量、7 天内到期数、超额停用的订阅用户数）；按分组/标签筛选；按名称/CPU/流量/到期排序；搜索；离线节点灰化并显示离线时长；点击进入详情。

### 4.2 节点详情

主机信息（系统、内核、架构、CPU 型号、agent 版本、公网 IP、开机时间）；曲线：CPU、内存、磁盘、上下行速率、TCP/UDP 连接数；每个 ping 任务的延迟曲线与丢包率。时间范围 1h / 24h / 7d / 30d：1h 与 24h 读分钟表，7d 与 30d 读小时表。

### 4.3 节点管理

| 分组 | 字段 |
|---|---|
| 基础 | 名称、地区（国家码）、分组、标签、排序、备注 |
| 接入 | agent token（创建时显示一次，可重置）、一键安装命令（自动拼好） |
| 公网地址 | `public_host`：订阅里使用的 IP 或域名 |
| 账单 | 价格、货币、周期（月/季/年/一次性）、到期日、到期自动顺延 |
| 流量套餐 | 上限（0 = 不限）、每月重置日、统计模式（出站 / 入站 / 出+入 / max，默认 max）、带宽标签 |

### 4.4 Ping 任务（三网延迟）

全局任务表：名称、目标（IP 或域名）、类型（icmp / tcp）、间隔（默认 60 s）、作用节点（全部或指定）。预置三条：深圳电信、深圳联通、深圳移动，目标可用运营商在深圳的公共 DNS 之类的地址（例如电信 `202.96.134.33`、联通 `210.21.196.6`、移动 `211.136.192.6`），**以实测能通为准**。卡片展示每任务最近 30 次结果：方块按延迟着色（小于 100 ms 绿、小于 200 ms 黄、超时红），丢包率取同一窗口。

### 4.5 代理节点管理（每台节点一页）

**核心状态卡**：安装状态、已安装版本 vs 面板托管版本、运行状态、已应用修订号、防火墙类型、最后错误。按钮：安装 / 升级、重启、查看日志（最近 200 行，只读）。

**入站列表**：每行一个入站——协议、端口、备注、启用开关、当前用户数、本期流量。四种协议各自的表单：

| 协议 | 表单字段 | 自动生成 |
|---|---|---|
| VLESS + Reality | 端口（默认 443/TCP）、握手目标（默认 `www.microsoft.com:443`）、short_id 列表 | x25519 密钥对、short_id |
| Shadowsocks 2022 | 端口（TCP+UDP）、加密（`2022-blake3-aes-128-gcm`） | 服务端 PSK |
| Hysteria2 | 端口（UDP）、混淆 salamander（默认开）、服务端上/下行带宽（可空）、忽略客户端带宽 | 混淆密码 |
| TUIC v5 | 端口（UDP）、拥塞控制（默认 bbr）、零 RTT（默认关） | — |

**证书**：每个节点一张自签证书，Hysteria2 与 TUIC 共用；显示 SHA256 指纹与伪装 SNI（默认 `www.bing.com`）；可重新生成——重新生成会让旧订阅里的指纹失效，客户端需要刷新订阅。

**高级**：节点级附加 JSON（`outbounds`、`route`），合并进渲染结果。用途是中转链路（深圳入口 → 海外出口），二期做 UI，一期留字段。

### 4.6 订阅用户与限额

"订阅用户"是一个人（或一组设备），凭据挂在人身上，各节点通用。

| 分组 | 字段 |
|---|---|
| 基础 | 名称、备注、启用 |
| 凭据 | `uuid`（VLESS、TUIC）、`password`（Hysteria2、TUIC）、`ss_user_key`（SS2022 用户 PSK）——自动生成，可重生成 |
| 限额 | 总流量上限（0 = 不限）、重置日（每月 N 号 / 不重置）、到期时间 |
| 分配 | 入站多选，UI 提供"全选某节点" |
| 订阅 | `sub_token`（可重置） |

列表页：用量进度条（已用 / 上限）、到期倒计时、状态（正常 / 超额停用 / 到期停用 / 手动停用）、分配节点数；按钮：订阅链接（三种格式）、二维码、清零用量、重置 token。详情页：按节点分账表、最近 30 天用量曲线。

规则：

- `used ≥ limit` → 自动停用；到重置日清零并自动恢复
- `now > expire_at` → 停用；延长到期时间即恢复
- 手动停用优先级最高，自动规则不会把它恢复
- 停用 = 该用户从所有已分配入站的 `users[]` 里移除并下发，客户端立刻连不上

### 4.7 订阅输出

`GET /sub/{sub_token}?format=clash | clash-provider | singbox | uri`，默认 `clash`。

| 格式 | 内容 | 用途 |
|---|---|---|
| `clash` | 完整配置：proxies + proxy-groups + rules。规则模板在后台可编辑，`{{PROXIES}}` 与 `{{PROXY_NAMES}}` 占位 | Clash 直接导入 |
| `clash-provider` | 只有 `proxies:` 列表 | 作为 proxy-provider 引入自己的规则配置 |
| `singbox` | outbounds JSON，证书 PEM 内嵌，客户端做正常校验 | sing-box 系客户端 |
| `uri` | base64 的 `vless:// ss:// hysteria2:// tuic://` 列表 | Shadowrocket 等 |

响应头：`subscription-userinfo: upload=…; download=…; total=…; expire=…`（Clash 客户端据此显示流量与到期）、`profile-update-interval: 24`、`content-disposition: attachment; filename=…`。

代理命名：`{节点名} · {协议}`，如 `香港-cst-01 · HY2`。节点离线也照常输出，客户端自动测速会跳过。

**客户端必须是 Meta/mihomo 内核**（Clash Verge Rev、Clash Meta for Android、ClashX Meta、mihomo party 等）。原版 Clash 已停更，不支持 Hysteria2、TUIC、Reality。

### 4.8 账单与到期

价格、货币、周期、到期日；到期自动顺延（年付到期自动 +1 年）；到期前 7 / 3 / 1 天提醒。卡片显示"到期 N 天"和"¥99/年"标签。

### 4.9 节点流量套餐

`limit`、`reset_day`、`mode`（out / in / sum / max，默认 max）。卡片显示剩余与进度条，`limit = 0` 显示 ∞。用量到 80% / 90% / 100% 提醒。结算规则见 6.5。

### 4.10 告警

| 规则 | 默认阈值 |
|---|---|
| 节点离线 | 持续 3 分钟 |
| CPU / 内存 / 磁盘 | 90%，持续 10 分钟 |
| 节点流量套餐 | 80% / 90% / 100% |
| 节点到期 | 提前 7 / 3 / 1 天 |
| ping 丢包 | 某任务 30 次窗口内丢包 ≥ 30% |
| 订阅用户用量 | 80% / 100%（通知管理员） |
| sing-box 应用失败 / 进程异常退出 | 立即 |

渠道：Telegram Bot、通用 Webhook。同一事件冷却 30 分钟；恢复时发恢复通知。

### 4.11 系统与安全设置

管理员账号密码、TOTP 开关、站点标题、时区（默认 Asia/Shanghai）、流量单位（1000 或 1024）、ping 数据保留天数、sing-box 托管版本管理（上传 CI 产物、设为当前版本）、审计日志查看。

## 5. Agent 设计

### 5.1 进程与文件

| 项 | 路径 |
|---|---|
| agent 二进制 | `/usr/local/bin/vps-agent` |
| agent 配置 | `/etc/vps-agent/config.yaml`（server、token、可选网卡白名单/挂载点） |
| agent 数据 | `/var/lib/vps-agent/`（下载缓存、上次已应用修订号） |
| systemd | `vps-agent.service`、`sing-box.service` |
| sing-box 二进制 | `/usr/local/bin/sing-box` |
| sing-box 配置 | `/etc/sing-box/config.json`、`config.json.bak`（上一份可用配置） |
| sing-box 日志 | `/var/log/sing-box/box.log` |

agent 以 root 运行（要写 sing-box 配置、重启服务、放行端口、发 ICMP），但**不监听任何端口**。

### 5.2 采集项

| 类别 | 频率 | 内容 |
|---|---|---|
| 静态 | 连上时一次，之后每 5 分钟 | hostname、OS、内核、架构、CPU 型号/核数、内存/磁盘总量、开机时间、agent 版本、IPv4/IPv6 可用性、公网 IP |
| 动态 | 每 1 秒 | CPU%、内存/swap 已用、磁盘已用、load 1/5/15、网卡累计收发字节与速率、TCP/UDP 连接数、进程数、uptime |
| ping | 按任务间隔（默认 60 s） | 每目标一次 ICMP（或 TCP 连接耗时），超时记丢包 |
| sing-box 统计 | 每 10 秒 | 每入站、每用户的 uplink/downlink **增量**（5.4） |

注意事项：网卡排除 `lo`、`docker*`、`veth*`、`br-*`、`tun*`、`tailscale*`，否则流量翻倍；累计字节用自开机以来的计数器，重启归零由 Server 处理（6.5）；CPU% 用 `/proc/stat` 两次采样差值。

### 5.3 连接

- WSS 到 `wss://面板域名/api/agent/ws`，握手头 `Authorization: Bearer {agent_token}`、`X-Agent-Version`
- 连上先发 `hello`（静态信息 + 当前已应用修订号 + sing-box 状态），Server 回 `config`（上报间隔、ping 任务）并在需要时补发 `core.apply` 对齐期望状态
- 每 1 秒一条 `metrics`；Server 15 秒没收到即判离线
- 断线指数退避重连（1 s → 60 s），不缓存离线期间的秒级数据（累计流量靠计数器，不受影响）

### 5.4 corectl：sing-box 受控执行器

**只接受这几种消息，没有"执行命令"**：

| 消息 | 动作 |
|---|---|
| `core.action install` | 从面板下载指定版本二进制，校验 sha256，安装，写 unit |
| `core.apply` | 应用一份完整配置（含修订号、sha256） |
| `core.action start / stop / restart` | 操作 `sing-box.service` |
| `core.logs` | 回传日志尾部 |

**安装流程**：`GET {面板}/api/agent/corefiles/{文件名}`（带 agent token）→ 校验 sha256 与消息中一致 → 写入 `/usr/local/bin/sing-box.new` → `sing-box.new version` 能跑 → 原子替换 → 写 `sing-box.service`（`ExecStart=/usr/local/bin/sing-box run -c /etc/sing-box/config.json`，`Restart=on-failure`，`LimitNOFILE=infinity`）→ `daemon-reload`、`enable` → 上报 `core.state`。

**应用流程**：

1. 修订号 ≤ 已应用且 sha256 相同且进程在跑 → 直接回报当前状态，不动
2. 写 `/etc/sing-box/config.json.new`
3. `sing-box check -c config.json.new`，失败 → 上报错误（带 stderr），结束
4. 当前配置备份为 `config.json.bak`，`.new` 原子替换为 `config.json`
5. `systemctl restart sing-box`
6. 5 秒内检查：`is-active`；配置里声明的端口是否在监听（读 `/proc/net/tcp*`、`/proc/net/udp*`）
7. 成功 → 记录已应用修订号，上报 `core.state`；失败 → 恢复 `.bak`，重启，上报错误。**回滚也失败**时上报 `running=false`，由面板告警

**端口放行**：应用前检测 `ufw`（active 才动）或 `firewalld`，放行配置中声明的 TCP/UDP 端口；两者都没有则不做，只在 `core.state.firewall` 里报 `none`，前端提示"请在云控制台放行"。

**统计流程**：gRPC 连 `127.0.0.1:10085`，sing-box 自己的 `experimental.v2rayapi.StatsService`（proto 从 sing-box 仓库 `experimental/v2rayapi/stats.proto` 拷贝后自行生成，避免把整个 sing-box 作为依赖编进 agent），每 10 秒 `QueryStats(pattern="", reset=true)`，解析 `user>>>sub-1>>>traffic>>>uplink`、`inbound>>>vless-443>>>traffic>>>downlink` 这类计数器名。`uplink` = 客户端上传，`downlink` = 客户端下载。

### 5.5 安装与卸载

```
curl -fsSL https://面板域名/install.sh | bash -s -- --server wss://面板域名 --token {agent_token}
```

脚本：检测架构 → 从面板下载 `vps-agent-linux-{arch}` → 写 `/etc/vps-agent/config.yaml` → 写 `vps-agent.service`（`Restart=always`）→ `enable --now` → 打印状态。`uninstall.sh` 反向执行，可选 `--purge-core` 一并卸掉 sing-box。

## 6. Server 设计

### 6.1 模块与目录

```
server/
├── cmd/server/main.go
└── internal/
    ├── hub/        agent.go（Agent Hub）、client.go（Client Hub）、state.go（最新状态）
    ├── api/        REST 路由与 handler，按资源分文件
    ├── auth/       密码、JWT、TOTP、登录限速
    ├── store/      SQLite 访问、迁移（golang-migrate 或 goose）、各表 repo
    ├── metrics/    分钟聚合、降采样、保留清理
    ├── traffic/    节点流量结算（账期、模式）
    ├── ping/       任务下发、结果存储
    ├── proxy/
    │   ├── render/   sing-box 配置渲染（第 9 节）
    │   ├── keys/     uuid、x25519、PSK、密码生成
    │   ├── certs/    自签证书
    │   ├── sub/      订阅输出（第 10 节）
    │   ├── enforce/  限额/到期检查、变更合并下发
    │   └── state.go  节点核心状态、修订
    ├── corefiles/  sing-box 二进制托管
    ├── alert/      规则评估、通知渠道
    ├── audit/      审计日志
    └── web/        embed.FS，前端构建产物
```

### 6.2 Agent Hub 与在线判定

按 token 哈希查节点；一个节点同时只允许一条连接（新连接踢旧连接）；维护 `map[serverID]*State`（最新 metrics、host info、ping 最近值、core 状态）。每 5 秒扫一遍 `last_seen`，超过 15 秒标离线并广播；离线持续达到告警阈值再发通知，避免抖动。

### 6.3 Client Hub 与快照

浏览器 WSS `/api/ws`，建连后 5 秒内必须发 `{type:"auth", token}`（JWT），否则断开。一个定时器每秒把全部节点状态序列化**一次**广播（十几台约 10 KB，开 permessage-deflate）。ping 历史不进快照，前端每 60 秒单独拉。

### 6.4 时序聚合与保留

秒级数据不落库。内存里按节点按分钟聚合：cpu avg/max、mem_used avg、disk_used last、load1 avg、rx/tx rate avg/max、rx/tx total last、连接数 avg、进程数 last，每分钟写一行 `metrics_minute`。每小时任务把上一小时的分钟行聚合到 `metrics_hour`。保留：分钟 7 天，小时 365 天，ping 结果 30 天（可调）。

### 6.5 节点流量结算

每条 `metrics` 携带 `rx_total / tx_total`：

- `delta = new − last`；若 `new < last`（重启归零）则 `delta = new`
- delta 累加到当前账期 `traffic_periods` 的 `in_bytes / out_bytes`
- 每天 00:00（面板时区）检查：今天是该节点 `reset_day` → 关闭当前账期，开新账期。重置日为 29–31 而当月没有该日时取当月最后一天
- 已用 = 按 `mode` 取：`out`、`in`、`sum`、`max(in, out)`；剩余 = `limit − 已用`

### 6.6 proxy 子系统

**render**：由节点的 inbounds + 分配到这些 inbounds 的启用用户 + 节点证书 + 高级 JSON → 完整 `config.json`，计算 sha256，修订号 +1，存 `config_revisions`。规则见第 9 节。

**keys**：

| 用途 | 生成 |
|---|---|
| VLESS / TUIC uuid | UUID v4 |
| Reality | x25519 私钥/公钥（`golang.org/x/crypto/curve25519`）；short_id 8 字节随机 hex |
| SS2022 | 服务端 PSK、用户 PSK：16 字节随机，base64 |
| Hysteria2 / TUIC 密码 | 24 字节随机，base64url |
| 混淆密码 | 同上 |

**certs**：每节点一张自签证书——ECDSA P-256，有效期 3650 天，CN 与 SAN 为伪装 SNI；存 PEM 与 DER 的 SHA256 指纹（`AB:CD:…` 形式）。

**sub**：见第 10 节。

**enforce**：每 60 秒跑一次——汇总 `subscriber_traffic` 到 `traffic_used`，判断超额与到期，改状态，标记受影响节点；节点级变更合并：同一节点 5 秒内的多次改动合成一次渲染下发，一个节点同时只有一次 apply 在飞；失败按 10 s、30 s、60 s 重试三次，仍失败则告警。

**corefiles**：CI 产物放 `{data}/corefiles/sing-box-{version}-linux-{arch}` 及 `.sha256`；后台"设为当前版本"；`GET /api/agent/corefiles/{name}` 需 agent token。

### 6.7 认证

- 密码 argon2id；JWT HS256，有效 12 小时，前端存 sessionStorage（Minimal starter 默认）
- 登录限速：同 IP 15 分钟内 5 次失败即锁 15 分钟
- TOTP 可选：开启后 `sign-in` 返回 `{ mfaRequired: true, ticket }`，再 `POST /api/auth/mfa { ticket, code }` 换 `accessToken`。starter 的登录页要加这一步
- 所有 `/api/**` 除 `auth/sign-in`、`auth/mfa`、`agent/**`、`/sub/**` 外都要 JWT

### 6.8 定时任务一览

| 频率 | 任务 |
|---|---|
| 1 s | 浏览器快照广播 |
| 5 s | 离线扫描 |
| 60 s | 分钟聚合落库；订阅用户用量汇总与限额/到期检查；节点流量统计落库 |
| 60 s | 告警规则评估（含冷却与恢复） |
| 1 h | 小时降采样；保留期清理 |
| 每日 00:00 | 节点账期与订阅用户账期滚动；到期自动顺延 |
| 每日 09:00 | 到期提醒汇总 |

## 9. sing-box 配置渲染规范

### 9.1 版本策略

面板钉住一个 sing-box 版本（开工时取最新稳定版 1.1x），渲染器只针对这个版本的字段写。sing-box 1.10 → 1.11 → 1.12 一路在废弃旧字段（例如入站的 `sniff` 移到路由规则动作），**升核心是面板的一次正式发版**：改渲染器、跑回归、更新托管二进制，再让节点升级。

### 9.2 构建

GitHub Actions 矩阵 linux/amd64、linux/arm64：

```bash
git clone --depth 1 --branch v1.1x.y https://github.com/SagerNet/sing-box
cd sing-box
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath \
  -tags "with_quic,with_utls,with_v2ray_api" \
  -ldflags "-s -w -buildid= -X github.com/sagernet/sing-box/constant.Version=v1.1x.y" \
  -o dist/sing-box-v1.1x.y-linux-amd64 ./cmd/sing-box
./dist/sing-box-v1.1x.y-linux-amd64 version   # 输出的 Tags 必须包含 with_v2ray_api
sha256sum dist/* > dist/SHA256SUMS
```

标签集以钉住版本的官方"Build from source"文档为准：默认集去掉 `with_clash_api`（我们不用，且与 V2Ray API 的流量 tracker 互相覆盖），加上 `with_v2ray_api`；`with_gvisor`、`with_wireguard`、`with_dhcp`、`with_tailscale` 服务端用不着，去掉减小体积。产物上传到面板 corefiles。

### 9.4 渲染规则

- 入站 `tag` = `{协议简称}-{端口}`；用户 `name` = `sub-{subscriber_id}`——这两个名字就是统计计数器的 key，改名等于重新计数
- 只渲染 `enabled = true` 且未被自动停用、且分配到该入站的用户；一个入站一个用户都没有时仍渲染入站（保持端口在线），`users` 为空数组
- `v2ray_api.stats.inbounds / users` = 该节点本次渲染出的全部 tag 与用户名
- 证书从 `certs` 表按行拆成数组内联，agent 不管文件
- `node_advanced.extra_json` 的 `outbounds`、`route` 与骨架**合并**：附加的 outbounds 追加；附加的 route.rules 插到 `sniff` 之后、`final` 之前；附加的 `final` 覆盖默认
- 渲染后用面板本地的同版本 `sing-box check` 预检一次（面板容器里也放一份二进制），错的配置不下发

### 9.5 已知坑

- `stats.enabled` 不为 true 时，V2Ray API 会对所有调用返回 `Unimplemented`
- 不要同时启用 `clash_api`：两者的流量 tracker 会互相覆盖（sing-box issue #2742）
- Reality 握手目标要选支持 TLS 1.3 + HTTP/2 的大站，且离节点地理位置近；国内节点别用被墙的目标
- Hysteria2 `ignore_client_bandwidth=false` 时客户端可以声明带宽，服务端会照做——家人朋友的客户端配置别乱填
- 修订号只增不减；agent 断线重连时用 `hello.applied_revision` 对齐，Server 发现落后即补发

## 10. 订阅格式规范

### 10.1 Clash（默认）

四个协议在 mihomo 里的写法：

```yaml
proxies:
  - name: "香港-cst-01 · VLESS"
    type: vless
    server: 1.2.3.4
    port: 443
    uuid: "{uuid}"
    network: tcp
    udp: true
    tls: true
    flow: xtls-rprx-vision
    servername: www.microsoft.com
    client-fingerprint: chrome
    reality-opts:
      public-key: "{x25519 公钥}"
      short-id: "{short_id}"

  - name: "香港-cst-01 · SS"
    type: ss
    server: 1.2.3.4
    port: 8388
    cipher: 2022-blake3-aes-128-gcm
    password: "{服务端 PSK}:{用户 PSK}"
    udp: true

  - name: "香港-cst-01 · HY2"
    type: hysteria2
    server: 1.2.3.4
    port: 8443
    password: "{密码}"
    obfs: salamander
    obfs-password: "{混淆密码}"
    sni: www.bing.com
    skip-cert-verify: false
    fingerprint: "{证书 SHA256 指纹}"
    alpn: [h3]

  - name: "香港-cst-01 · TUIC"
    type: tuic
    server: 1.2.3.4
    port: 8444
    uuid: "{uuid}"
    password: "{密码}"
    alpn: [h3]
    sni: www.bing.com
    skip-cert-verify: false
    fingerprint: "{证书 SHA256 指纹}"
    congestion-controller: bbr
    udp-relay-mode: native
    reduce-rtt: true
```

要点：Hysteria2 与 TUIC 用 `fingerprint` pin 自签证书，`skip-cert-verify` 保持 false；`sni` 与证书 SAN 一致。默认的 proxy-groups 与 rules 模板：

```yaml
proxy-groups:
  - name: 节点选择
    type: select
    proxies: [自动选择, DIRECT, {{PROXY_NAMES}}]
  - name: 自动选择
    type: url-test
    url: https://www.gstatic.com/generate_204
    interval: 300
    tolerance: 50
    proxies: [{{PROXY_NAMES}}]
rules:
  - GEOSITE,private,DIRECT
  - GEOSITE,cn,DIRECT
  - GEOIP,private,DIRECT,no-resolve
  - GEOIP,CN,DIRECT
  - MATCH,节点选择
```

`clash-provider` 格式只输出 `proxies:` 段。

### 10.2 sing-box

输出 `outbounds` 数组：`vless`（`flow: xtls-rprx-vision`，`tls.reality.public_key / short_id`，`tls.utls.fingerprint: chrome`）、`shadowsocks`（`password` 为 `服务端PSK:用户PSK`）、`hysteria2`（`obfs`，`tls.certificate` 内嵌 PEM，`tls.server_name` = 伪装 SNI）、`tuic`（`congestion_control: bbr`，`tls.certificate` 内嵌）。内嵌证书后客户端做正常校验，不需要 `insecure`。

### 10.3 URI 列表

```
vless://{uuid}@{host}:443?encryption=none&flow=xtls-rprx-vision&security=reality&sni=www.microsoft.com&fp=chrome&pbk={公钥}&sid={short_id}&type=tcp#{名称}
ss://2022-blake3-aes-128-gcm:{服务端PSK}:{用户PSK}@{host}:8388#{名称}
hysteria2://{密码}@{host}:8443/?sni=www.bing.com&insecure=0&pinSHA256={指纹}&obfs=salamander&obfs-password={混淆密码}#{名称}
tuic://{uuid}:{密码}@{host}:8444?congestion_control=bbr&alpn=h3&sni=www.bing.com&udp_relay_mode=native&allow_insecure=1#{名称}
```

TUIC 没有统一的 URI 标准，按 v2rayN / NekoBox 的写法输出，且这些客户端多半不支持指纹 pin，只能 `allow_insecure=1`——这是 `uri` 格式排在最后的原因。

### 10.4 用量头

```
subscription-userinfo: upload={up}; download={down}; total={limit}; expire={unix}
profile-update-interval: 24
content-disposition: attachment; filename="{订阅用户名}.yaml"
```

`total` 在不限额时省略，`expire` 在无到期时省略。

首次启动打印初始管理员密码到日志；`data/` 里是 SQLite、corefiles、agent 二进制。可选加一层访问限制：Caddy 只放行自己的 IP 段，或放到 Cloudflare Access / Tailscale 后面。

### 12.2 Agent

后台"节点"页复制一键安装命令（5.5）。升级：面板发新 agent 版本后，agent 收到 `agent.update` 消息自下载替换重启（阶段 5 做；之前手动重跑安装脚本即可）。

### 12.3 备份与恢复

每日 `sqlite3 data/vm.db ".backup data/backup/vm-$(date +%F).db"` 保留 14 天；`corefiles` 可从 CI 重新拉。恢复 = 替换 db 文件后重启 server；agent 重连即恢复实时状态，节点配置由修订号对齐后自动补发。

### 12.4 升级顺序

1. 面板：换镜像 `docker compose pull && up -d`，迁移自动跑
2. sing-box：CI 产出新版本 → 上传 corefiles → 设为当前版本 → 在代理页逐台点"升级"（升级 = 装新二进制 + 重启，断连几秒）
3. agent：新版本先在一台上验证，再全量

### 12.5 CI

三条流水线：`agent`（Go 交叉编译两架构 + 上传面板）、`server`（前端 build → Go embed → 镜像）、`sing-box`（9.2 的构建，按 tag 触发，产物附 SHA256SUMS）。

## 13. 安全设计

- **agent 指令白名单**：无任意命令执行；每条消息做 schema 校验；只写固定路径、只操作固定 unit
- **面板私有**：整站登录；JWT 12 小时；argon2id；登录限速；TOTP；建议网络层再限一道（IP 白名单 / Cloudflare Access / Tailscale）
- **token 分离**：每节点独立 agent token（只存哈希，可重置）；每订阅用户独立 sub_token（可重置）；泄露影响范围局限
- **sing-box API 仅本机**：`127.0.0.1:10085`
- **证书 pin**：Hy2 / TUIC 订阅默认带指纹，不默认 `insecure`
- **审计**：所有写操作记 `audit_log`（谁、何时、改了什么、改前改后）
- **传输**：agent、浏览器、订阅全部 TLS；订阅 URL 不进访问日志正文（Caddy 日志脱敏 `/sub/*` 路径）
- **供应链**：sing-box 与 agent 二进制由自己的 CI 构建并附 sha256，agent 下载后校验
